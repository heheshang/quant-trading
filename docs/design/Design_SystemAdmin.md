## 1. 页面概述与目标

### 1.1 页面定位

系统管理页面用于管理量化交易系统的用户账号、角色权限和系统配置。管理员可进行用户 CRUD 操作、角色权限分配等操作。

### 1.2 核心功能

- **用户管理**：用户列表、创建用户、编辑用户、删除用户、禁用/启用用户
- **角色管理**：角色列表、创建角色、编辑角色权限、删除角色
- **权限配置**：可视化权限树、角色绑定用户
- **操作日志**：用户操作审计（查看权限）

### 1.3 用户角色

- 超级管理员（SuperAdmin）：所有权限
- 管理员（Admin）：用户管理、角色管理
- 审计员（Auditor）：仅查看权限

## 3. 核心交互流程

### 3.1 用户管理流程

#### 创建用户
1. 点击「新建用户」按钮
2. 弹出用户创建对话框
3. 填写：用户名、邮箱、初始密码、角色
4. 调用 `POST /api/admin/users`
5. 成功后关闭对话框并刷新表格

#### 编辑用户
1. 点击用户行「编辑」按钮
2. 弹出编辑对话框（预填数据）
3. 修改字段（密码需确认才可修改）
4. 调用 `PUT /api/admin/users/:id`
5. 成功刷新

#### 删除/禁用用户
1. 点击「删除」或「禁用」按钮
2. 确认对话框（禁用：提示影响范围）
3. 调用 `DELETE /api/admin/users/:id` 或 `PUT /api/admin/users/:id/disable`
4. 成功刷新

### 3.2 角色管理流程

#### 创建角色
1. 点击「新建角色」按钮
2. 弹出角色创建对话框
3. 填写：角色名、描述、权限列表（多选）
4. 调用 `POST /api/admin/roles`
5. 成功后关闭对话框

#### 权限配置
1. 点击角色行「编辑权限」按钮
2. 展开权限配置面板（右侧抽屉）
3. 勾选/取消权限节点
4. 自动保存或点击「保存」手动保存
5. 调用 `PUT /api/admin/roles/:id/permissions`

### 3.3 搜索与筛选

1. 搜索框输入关键词（用户名/邮箱）
2. 300ms 防抖后触发搜索
3. 调用 `GET /api/admin/users?search=xxx&role=xxx&status=xxx`
4. 下拉筛选即时生效

## 4. 状态设计

### 4.1 加载状态

- 页面初始：骨架屏表格
- 对话框加载：表单区域 skeleton
- 操作执行：按钮 loading

- 无用户：空状态插图 + 「暂无用户，点击新建」

- 创建失败：对话框内错误提示

- 权限不足：弹窗提示

| 状态 | 样式 |
|------|------|

| 禁用用户 | 行灰度 + 「已禁用」标签 |

## 5. API 调用说明

### 5.1 接口列表

| 方法 | 端点 | 描述 |
|------|------|------|
| GET | `/api/admin/users` | 获取用户列表（分页） |
| GET | `/api/admin/users/:id` | 获取单个用户 |
| POST | `/api/admin/users` | 创建用户 |
| PUT | `/api/admin/users/:id` | 更新用户 |
| DELETE | `/api/admin/users/:id` | 删除用户 |
| PUT | `/api/admin/users/:id/disable` | 禁用用户 |
| PUT | `/api/admin/users/:id/enable` | 启用用户 |
| GET | `/api/admin/roles` | 获取角色列表 |
| POST | `/api/admin/roles` | 创建角色 |
| PUT | `/api/admin/roles/:id` | 更新角色 |
| DELETE | `/api/admin/roles/:id` | 删除角色 |
| PUT | `/api/admin/roles/:id/permissions` | 更新角色权限 |
| GET | `/api/admin/permissions` | 获取所有权限点 |

### 5.2 数据类型

```typescript
interface User {
  id: string
  username: string
  email: string
  role: Role
  status: 'active' | 'disabled'
  created_at: string
  updated_at: string
}

interface Role {
  id: string
  name: string
  description: string
  permissions: string[]
  users_count: number
  created_at: string
}

interface Permission {
  id: string
  code: string
  name: string
  group: string
}
```
