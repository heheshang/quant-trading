## 1. 设计原则与设计决策

### 1.1 核心设计原则

| # | 原则 | 说明 |
|---|------|------|
| 1 | **状态驱动视图切换** | 配置/运行中/结果三模式通过单一状态变量驱动，不拆子路由 |
| 2 | **渐进式数据加载** | KPI 指标优先加载（页面核心），权益曲线和交易明细按需加载（Lazy Tab） |
| 3 | **进度透明** | 回测运行时提供进度百分比、当前 K 线位置、已用时间三项信息 |
| 4 | **容错优先** | 每个状态都有对应的错误处理：配置校验错误→行内提示，运行错误→带重试的错误视图 |
| 5 | **移动优先回退** | 复杂结果卡片在移动端折叠为带展开的摘要行 |

### 1.2 关键设计决策

| 决策 | 选择 | 理由 |
|------|------|------|
| 配置/结果同页面 | 单页面 + 状态切换（而非子路由） | MVP 阶段简化路由；配置→结果→重新配置是高频循环 |
| 绩效指标卡片顺序 | 总收益 / 夏普 / 最大回撤 / 胜率 为 Top4 | 这是交易者最关心的 KPI 金字塔 |
| 权益曲线加载策略 | 结果返回后才延迟加载（include_curve=true） | 曲线数据可能很大，页面先展示 KPI 再请求曲线 |
| 交易明细分页 | 前端分页（一次性渲染全部数据做虚拟滚动） | 回测交易数通常 < 500 条，前端分页更流畅 |
| 进度模式 | 进度条 + K 线计数 + 已用时间 | UX Pro Max: "显示多步进度" 优于纯百分比 |

## 2. 页面路由与状态机

### 2.1 路由

| 路径 | 组件 | 模式 |
|------|------|------|
| `/backtest` | `BacktestView.vue` | 状态驱动切换（不拆子路由） |

### 2.2 状态机

```
                    ┌──────────────────┐
                    │    idle (默认)    │  ← 初始加载，显示配置表单
                    └────────┬─────────┘
                             │ 用户填写参数点击"运行回测"
                             ▼
                    ┌──────────────────┐
                    │    validating    │  ← 前端校验参数
                    └────────┬─────────┘
                             │ 校验通过 → POST /backtest/run
                             ▼
                    ┌──────────────────┐
                    │    pending       │  ← 202 Accepted，等待后台调度
                    └────────┬─────────┘
                             │ WS/轮询 status = running
                             ▼
                    ┌──────────────────┐
                    │    running       │  ← 显示进度条 + 当前 K 线信息
                    └────────┬─────────┘
                    ┌────────┴─────────┐
                    │                  │
                    ▼                  ▼
            ┌──────────────┐   ┌──────────────┐
            │  completed   │   │    failed    │  ← 显示错误 + 重试按钮
            └──────┬───────┘   └──────────────┘
                   │ 用户点击"重新回测"
                   ▼
            ┌──────────────┐
            │    idle      │  ← 回到配置模式（保留上次参数）
            └──────────────┘

另：running 状态下用户可点击"取消" → cancelled
cancelled → idle（保留参数）
```

### 2.3 状态枚举与视图映射

| 状态值 | 视图模式 | 说明 |
|--------|---------|------|
| `idle` | config | 显示配置表单，无结果 |
| `validating` | config | 配置表单进入校验动画 |
| `pending` | progress | "排队中..." 状态 |
| `running` | progress | 进度条 + 当前处理信息 |
| `completed` | result | 绩效报告 + 图表 + 交易明细 |
| `failed` | error | 错误信息 + 重试按钮 |
| `cancelled` | config | Toast "回测已取消" + 配置恢复 |

- 点击"取消回测" → 确认对话框 "确定要取消当前回测吗？" [确认] [取消]
- 确认后 → POST `/api/v1/backtest/{id}/cancel`
- 响应成功 → 状态切到 cancelled → Toast "回测已取消"
- 响应失败（如回测已结束）→ Toast "取消失败：回测已完成"

### 10.3 WebSocket 对接

连接建立后，前端订阅 `backtest_progress` 频道：

```typescript
// 连接 WS
const ws = new WebSocket(`wss://host/api/v1/market/ws?token=${token}`)

// 订阅回测进度
ws.send(JSON.stringify({
  action: 'subscribe',
  channels: [`backtest_progress:${currentRunId}`]
}))

// 处理消息
ws.onmessage = (event) => {
  const msg = JSON.parse(event.data)
  if (msg.type === 'backtest_progress') {
    progress.value = msg.data.progress
    currentBar.value = msg.data.current_bar
    totalBars.value = msg.data.total_bars
    elapsedMs.value = msg.data.elapsed_ms
  }
  if (msg.type === 'backtest_completed') {
    // 拉取结果
    fetchResult()
  }
}
```

**断线重连策略：**
- WS 断开自动切到轮询：`GET /api/v1/backtest/{id}/progress`，每 2s
- WS 恢复后切回实时推送
- 最大重连次数：5 次，指数退避
