## 概述

K 线数据管理模块负责量化交易系统中 K 线（蜡烛图）数据的全生命周期管理。通过本模块，用户可以：

- 从 CSV 文件、API 或交易所批量导入 K 线数据
- 按交易对、周期、时间范围分页查询数据
- 自动检测数据质量问题（缺尖、异常值、重复等）
- 一键清洗数据（自动备份、线性插值填充、去重、异常标记）
- 导出数据为 CSV 或 JSON 格式

### 用户角色

| 角色 | 权限 |
|------|------|
| `trader` | 导入、查询、导出、质量检测、清洗、删除 |
| `pro-trader` | trader 全部权限 + 交易所直采（P2 阶段） |
| `admin` | 跨用户审计查询（只读） |

## 核心概念

### K 线周期

系统支持 8 种标准 K 线周期：

| 周期 | 枚举值 | 典型用途 |
|------|--------|----------|
| 1 分钟 | `1m` | 高频策略、实时监控 |
| 5 分钟 | `5m` | 日内短线策略 |
| 15 分钟 | `15m` | 日内波段策略 |
| 30 分钟 | `30m` | 短期趋势分析 |
| 1 小时 | `1h` | 中短期策略回测 |
| 4 小时 | `4h` | 中期趋势判断 |
| 1 天 | `1d` | 中长期策略 |
| 1 周 | `1w` | 长期趋势分析 |

### 数据来源

| 来源 | 枚举值 | 说明 |
|------|--------|------|
| CSV 文件 | `csv` | 上传本地 CSV 文件，适合批量导入历史数据 |
| API | `api` | 通过 JSON 数组上传，适合程序化导入 |
| 交易所直采 | `exchange` | 直接从交易所 API 拉取（P2 阶段，仅 pro-trader） |

### 数据质量状态

| 状态 | 说明 |
|------|------|
| 正常 | 数据通过所有校验规则 |
| 缺失 | 存在时间缺口（超过 2 倍 interval 无数据） |
| 异常 | 数值超出合理范围（偏离 5 日均值 ±15%） |
| 重复 | 相同 `open_time` 的数据条目 |
| 可疑 | 已标记为需人工复核的数据 |
| 损坏 | 已标记为损坏的数据 |

## 导入 K 线数据

### 操作流程

1. **进入导入页面**
   导航至 `/klines/import`，或从 K 线列表页点击「+ 导入」按钮。

2. **选择数据来源**
   - **CSV 文件**：拖拽或点击上传区域选择文件
   - **API 导入**：切换至 API 模式，粘贴 JSON 数据

3. **填写导入配置**

   | 字段 | 说明 | 示例 |
   |------|------|------|
   | 交易对 | 从下拉列表选择或搜索 | `BTCUSDT` |
   | 周期 | 选择 K 线周期 | `1h` |
   | 数据来源 | CSV / API / 交易所 | `csv` |

4. **点击「开始导入」**
   系统将分片处理数据（5000 条/批次），实时显示进度条。

5. **查看导入结果**
   导入完成后显示统计信息：成功条数、重复条数、失败条数。

### CSV 文件格式

CSV 文件必须包含以下列（表头名称固定）：

| 列名 | 必填 | 格式 | 示例 |
|------|------|------|------|
| `open_time` | 是 | 毫秒时间戳 | `1704067200000` |
| `open` | 是 | 字符串数字 | `42000.00` |
| `high` | 是 | 字符串数字 | `42500.50` |
| `low` | 是 | 字符串数字 | `41800.00` |
| `close` | 是 | 字符串数字 | `42300.25` |
| `volume` | 是 | 字符串数字 | `1234.56` |
| `close_time` | 否 | 毫秒时间戳 | `1704070799999` |
| `quote_volume` | 否 | 字符串数字 | `52000000.00` |
| `trades` | 否 | 整数 | `8500` |

**CSV 示例：**

```csv
open_time,open,high,low,close,volume
1704067200000,42000.00,42500.50,41800.00,42300.25,1234.56
1704070800000,42300.25,42800.00,42100.00,42650.75,987.65
```

### 导入限制

| 限制 | 值 |
|------|------|
| 单次最大文件大小 | 100 MB |
| 单次最大数据条数 | 100,000 条 |
| 重复数据处理 | 跳过（`ON CONFLICT DO NOTHING`） |
| 性能目标 | 10 万条 CSV 数据 < 30 秒 |

### 导入进度

导入过程中，进度条实时更新已处理条数。状态文字说明：

| 状态 | 显示 |
|------|------|
| 进行中 | `导入中... 12,500 / 50,000` |
| 完成 | `导入完成 ✓ 成功 49,850 条` |
| 部分失败 | `导入完成 ⚠ 成功 49,850 条，失败 30 条` |
| 完全失败 | `导入失败 ✗ 失败原因` |

### 查看导入历史

导航至 K 线列表页，查看导入历史记录。每条记录包含：

- 交易对、周期、数据来源
- 总行数、成功/重复/失败条数
- 导入时间

## 查询 K 线数据

### 操作流程

1. **进入 K 线列表页**
   导航至 `/klines`。

2. **设置筛选条件**
   - **周期筛选**：点击顶部 Pills 切换（全部 / 1m / 5m / 15m / 30m / 1h / 4h / 1d / 1w）
   - **交易对**：从下拉列表选择或搜索
   - **时间范围**：选择起止日期时间

3. **浏览数据**
   表格显示匹配的 K 线数据摘要，包括数据点数、覆盖范围、质量状态。

4. **查看详情**
   点击行右侧 `⋮` 菜单 → 「查看详情」或「预览图表」。

### 查询参数说明

| 参数 | 必填 | 默认值 | 说明 |
|------|------|--------|------|
| `symbol` | 是 | — | 交易对 |
| `interval` | 是 | — | K 线周期 |
| `start_time` | 是 | — | 起始时间戳（毫秒） |
| `end_time` | 是 | — | 结束时间戳（毫秒） |
| `page` | 否 | 1 | 页码 |
| `page_size` | 否 | 1000 | 每页条数（最大 5000） |

### 注意事项

- 时间范围不得超过 10 年
- 数据按 `open_time` 升序排列
- 当连续超过 8 小时无数据时，系统会标记 `gap_detected`（如周末休市）
- 查询走 Redis 缓存优先，未命中再查数据库

## 数据质量检测

### 操作流程

1. **进入质量报告页面**
   导航至 `/klines/quality`。

2. **选择检测范围**
   - 交易对（必填）
   - 周期（必填）
   - 时间范围（必填）

3. **点击「生成报告」**
   系统对指定范围数据执行 5 项检测规则。

4. **查看报告**
   - **总览统计卡片**：总行数、有效行、覆盖率、缺口数、异常数、重复数
   - **覆盖率环形图**：直观显示数据完整程度
     - 绿色（>95%）：数据质量良好
     - 橙色（90%~95%）：数据存在少量问题
     - 红色（<90%）：数据质量堪忧，建议清洗
   - **异常数据列表**：逐条展示异常详情

### 检测规则详解

| 规则 | 检测逻辑 | 严重度 |
|------|----------|--------|
| 缺尖检测 | 超过 2 倍 interval 时间范围内无数据 | 高 |
| 异常值检测 | 价格偏离 5 日均值 ±15% | 中 |
| 重复检测 | 相同 `open_time` 的数据条目 | 中 |
| 零成交量 | `volume = 0` | 低 |
| 价格反向 | `high < low` | 高 |

### 覆盖率计算

```
coverage_rate = valid_rows / total_rows
```

- `valid_rows`：通过所有检测规则的数据行数
- `total_rows`：总数据行数（含异常和重复）

## 数据清洗

### 操作流程

1. **从质量报告发起清洗**
   在质量报告页面的异常数据列表中，点击「全部清洗」按钮。

2. **确认清洗**
   系统弹出确认弹窗，展示待清洗数据的统计信息：
   - 缺口数量
   - 重复数据条数
   - 异常数据条数

3. **执行清洗**
   点击「确认清洗」后，系统自动执行以下操作：

   | 步骤 | 操作 |
   |------|------|
   | 1. 创建备份 | 自动创建 `kline_backup` 快照（7 天过期），获取 `backup_id` |
   | 2. 缺尖填充 | 对缺口处进行线性插值填充 |
   | 3. 重复去重 | 相同 `open_time` 保留第一条，删除后续重复 |
   | 4. 异常标记 | 标记为 `suspicious` 或 `corrupted`，**不自动删除** |

4. **查看清洗结果**
   清洗完成后显示报告：
   - 填充缺口数
   - 去重条数
   - 标记可疑/损坏条数
   - 备份快照 ID（用于回滚）

### 清洗安全机制

- **自动备份**：每次清洗前自动创建备份快照，7 天自动过期
- **异常数据保留**：异常数据仅标记，不自动删除，避免误删有效数据
- **用户隔离**：只能清洗自己的数据

### 回滚（P2 阶段）

如清洗结果不符合预期，可通过 `backup_id` 回滚至清洗前状态：

```
DELETE /api/v1/kline/clean/rollback?backup_id=<backup_id>
```

> 回滚功能将在 P2 阶段实现。当前请务必在清洗前导出备份。

## 导出 K 线数据

### 操作流程

1. **从列表页发起导出**
   在 K 线列表页点击「导出」按钮，打开导出面板。

2. **选择导出配置**

   | 配置 | 选项 | 默认值 |
   |------|------|--------|
   | 格式 | CSV / JSON | CSV |
   | 字段 | 全部 / 自定义选择 | 全部字段 |
   | 交易对 | 当前筛选的交易对 | — |
   | 时间范围 | 当前筛选的时间范围 | — |

3. **点击「导出」**
   系统生成文件并触发浏览器下载。

### 导出格式

#### CSV 格式

- 文件名：`kline_{symbol}_{interval}_{start}_{end}.csv`
- 表头：`timestamp,open,high,low,close,volume,close_time,quote_volume,trades,exchange`
- 编码：UTF-8
- 适合：Excel 导入、第三方工具处理

#### JSON 格式

- 文件名：`kline_{symbol}_{interval}_{start}_{end}.json`
- 结构：数组，每个元素为 K 线数据对象
- 适合：程序化处理、数据迁移

### 大数据量导出

系统采用流式响应，无需担心内存溢出。大数据量导出时：

- 前端通过 XHR 流式下载
- 下载过程中按钮显示 spinner
- 完成后自动触发浏览器保存

## 删除 K 线数据

### 操作流程

1. **从列表页操作菜单发起**
   在 K 线列表页，点击行右侧 `⋮` 菜单 → 「删除数据」。

2. **二次确认**
   系统弹出确认弹窗，提示删除范围和不可逆警告。

3. **确认删除**
   点击「确认删除」，系统删除指定范围内的 K 线数据。

### 注意事项

- **操作不可逆**：删除前建议先导出备份
- **权限限制**：只能删除自己的数据
- **缓存失效**：删除后自动清除 Redis 中对应缓存

## 数据保留策略

K 线数据采用 TimescaleDB 分区存储，根据周期自动执行保留和压缩策略：

| 周期 | 保留期 | 压缩比 | 说明 |
|------|--------|--------|------|
| `1m` / `5m` | 30 天 | 8:1 | 超期数据自动删除 |
| `15m` / `30m` / `1h` | 1 年 | 4:1 | 年度数据自动压缩存储 |
| `4h` / `1d` / `1w` | 永久 | 2:1 | 长期保存，仅压缩 |

> **注意**：保留策略通过 TimescaleDB `drop_chunks_policy` 自动执行，无需手动清理。如需保留更长时间的低周期数据，请在过期前导出备份。

## 最佳实践

### 数据导入

1. **先小后大**：首次导入建议先用少量数据（100 条）验证格式正确性，再批量导入。
2. **避免重复**：系统使用 `(user_id, symbol, interval, open_time)` 复合唯一键自动去重，重复数据会被跳过。
3. **CSV 编码**：确保 CSV 文件使用 UTF-8 编码，避免中文乱码。
4. **时间戳格式**：`open_time` 必须为毫秒时间戳（13 位），如 `1704067200000`。
5. **价格格式**：`open`/`high`/`low`/`close`/`volume` 使用字符串格式，避免浮点精度丢失。

### 数据质量

1. **定期检测**：建议每次导入后执行质量检测，及时发现数据问题。
2. **关注覆盖率**：覆盖率低于 90% 时应优先清洗或补充数据。
3. **谨慎清洗**：清洗前确认备份已创建，异常数据仅标记不删除。
4. **周末缺口**：加密货币市场 7×24 小时运行，如检测到缺口需确认是否为数据源问题。

### 性能优化

1. **合理分页**：查询时使用合理的 `page_size`，避免一次请求过多数据。
2. **利用缓存**：重复查询相同范围的数据会命中 Redis 缓存，响应更快。
3. **大文件分片**：系统自动按 5000 条/批次分片处理，无需手动分批。
4. **流式导出**：大数据量导出自动走流式响应，不会占用过多内存。

## 常见问题

### Q: 导入时报「参数校验失败」？

A: 检查以下常见原因：
- CSV 文件缺少必需列（`open_time`, `open`, `high`, `low`, `close`, `volume`）
- `open_time` 不是有效的毫秒时间戳
- 价格/成交量不是有效的数字字符串
- `interval` 不在支持的周期列表中

### Q: 导入后为什么成功条数少于总条数？

A: 系统使用 `ON CONFLICT DO NOTHING` 策略，已存在的数据（相同 `user_id` + `symbol` + `interval` + `open_time`）会被跳过，记入 `duplicates`。部分格式错误的数据记入 `failed`。

### Q: 查询时 `gap_detected` 为什么是 `true`？

A: 当连续超过 8 小时无数据时，系统会标记 `gap_detected = true`。常见原因：
- 周末休市（传统金融资产）
- 数据源中断
- 导入时跳过了部分时间段

### Q: 清洗后能否恢复原始数据？

A: 清洗前系统会自动创建备份快照（7 天过期），返回 `backup_id`。P2 阶段将支持通过 `backup_id` 回滚。当前版本如需恢复，请在清洗前导出备份。

### Q: 为什么导出速度慢？

A: 大数据量导出采用流式响应，速度取决于数据量和网络带宽。建议：
- 缩小时间范围
- 使用 `fields` 参数仅导出需要的字段
- 选择 CSV 格式（比 JSON 更紧凑）

### Q: 删除数据后能否恢复？

A: **删除操作不可逆**。强烈建议删除前先导出数据备份。系统不会为删除操作创建备份。

### Q: 如何查看历史导入记录？

A: 通过 `GET /api/v1/kline/import-history` 端点，或在前端 K 线列表页查看导入历史，包含每次导入的统计信息。

### Q: 不同周期的数据保留策略是什么？

A: 1m/5m 周期数据保留 30 天，15m/30m/1h 保留 1 年，4h/1d/1w 永久保留。超期数据由 TimescaleDB 自动清理。如需保留更长时间，请在过期前导出备份。
