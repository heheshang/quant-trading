## 关键架构分析

1. **Sea-orm 兼容性**：Sea-orm 的 DeriveActiveModel 绑定单一表名，PostgreSQL 分区对应用透明
2. **最佳方案**：SQL 层创建分区 parent table，应用层代码零改动
3. **实现路径**：创建 `kline_partition_manager.rs` 服务 + SQL 迁移脚本
4. **Partition Key**：`open_time`（K线时间戳，按月 RANGE）

## 风险评估

| 风险 | 影响 | 缓解 |
|------|------|------|
| Sea-orm 不支持分区直接操作 | 低 | 应用层不感知，仅 SQL 层分区 |
| 历史数据迁移 | 低 | 新分区表，历史数据不动 |
| 定时任务管理 | 中 | 使用 tokio cron 内置定时器 |
