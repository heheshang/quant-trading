export interface DashboardStats {

**实际 JSON**（serialize 后）: `{ totalPnl, dailyPnl, winRate, sharpeRatio, totalTrades, activePositions, balance }`

**结论**: ✅ **已修复** — 字段名一一对应，camelCase JSON 与前端 `KlineResponse` 风格一致。

## 5. Kline API — `GET /api/v1/kline/query`

**后端**:
```rust
pub struct KlineResponse {
    pub id: i64,
    pub user_id: Uuid,
    pub symbol: String,
    pub interval: String,
    pub timestamp: i64,  // = open_time
    pub open_time: i64,
    pub open: f64, pub high: f64, pub low: f64, pub close: f64, pub volume: f64,
    pub close_time: Option<i64>,
    pub quote_volume: Option<f64>,
    pub trades: Option<i64>,
    pub source: String,
    pub created_at: chrono::DateTime<chrono::Utc>,
}

pub struct KlineListResponse {
    pub data: Vec<KlineResponse>,
    pub meta: KlineListMeta,
}
```

**前端** (`frontend/src/types/kline.ts`):
```typescript
export interface KlineData {
  open_time: number
  open: number; high: number; low: number; close: number; volume: number
  close_time?: number; quote_volume?: number; trades?: number; is_gap?: boolean
}

export interface KlineResponse {
  data: KlineData[]
  meta: { total: number; page: number; page_size: number; gap_detected?: boolean }
}
```

**结论**: ✅ **已修复** — 前端 `KlineData` 是后端 `KlineResponse` 的子集（前端只关心 OHLCV+time）。
后端多出的元数据字段（`id`/`user_id`/`symbol`/`source`/`created_at`）前端不消费，**无破坏性影响**。
响应嵌套 `{data: [...], meta: {...}}` 与前端 `KlineResponse` 一致。

> **预防建议**：为防止后续字段膨胀污染前端类型，可考虑在 backend 加一个 `KlineDataView` 视图 DTO，
> 只暴露前端子集。但当前 sub-set 兼容是 OK 的。

### 建议 — 持续维护

1. **加 CI 门禁**：用 `utoipa`（Rust OpenAPI）自动生成 spec，前端 `openapi-typescript` 同步类型
2. **字段命名规范文档化**：在 `docs/architecture/CONVENTIONS.md` 明确：
   - Rust 字段：`snake_case`（如 `total_pnl`）
   - JSON 序列化：默认 snake_case
   - 仅业务命名冲突时（如 `triggered_rule`）用 `#[serde(rename = "camelCase")]`
3. **新增 API 时强制走 T2 契约审查**（见 `tech-lead` skill 的 B1-B4 清单）
